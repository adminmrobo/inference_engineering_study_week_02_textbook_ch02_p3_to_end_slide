글 공장: 하나 만들고, 다시 넣고, 다음 하나

왼쪽 = 기계 한 번에 끝나는 보통 공장(분류), 오른쪽 = 자기회귀 조립 라인 설명용

무엇인가

글은 길고 앞뒤가 맞아야 해서 한 번에 못 만듭니다. 토큰 하나(글 조각)를 만들고, 지금까지 만든 줄을 다시 넣어 다음 하나를 고릅니다.

왜 효과적인가

① 매번 "다음 하나"만 맞히는 쉬운 문제 ② 앞에 만든 것을 보고 고르니 앞뒤가 맞음 ③ 길이를 미리 정하지 않아도 됨

대가

순서대로 하나씩이라 느림. 앞 계산은 작업 일지(KV 캐시)에 적어 다시 하지 않음. 이 "하나씩" 단계가 2.4의 디코드

무엇인가

잡음으로 가득 찬 판(거친 원석)에서 시작해, 공정마다 기계가 "어디가 잡음인지" 예측하고 조금씩 걷어 냅니다. 30–50번이면 그림이 드러납니다 책

왜 이렇게 하나

  • 그림은 칸 100만 개가 서로 맞아야 함
  • 한 칸씩이면 기계 100만 번, 앞의 실수는 못 고침
  • 전체를 함께 다듬으면 30–50번, 실수도 다음 번에 고침
대신 한 번 한 번이 그림 전체를 다루는 큰 일. 기계(계산)가 바빠지겠군.
복습 · 2.2 그림 2.3 행렬곱

설계도 한 번 들여와서, 제품 몇 개 만드나

앞 두 장의 "기계"가 하는 일은 대부분 행렬곱(그림 2.3, y = xW + b). 기계는 일할 때마다 창고에서 설계도(가중치 W)를 들여와야 합니다. 입력(자재) B개를 한 번에 넣으면
연산 = 2·B·d², 설계도 읽기 = 2·d² 바이트(FP16)

B=1이면 설계도 한 트럭 들여와서 제품 하나. 손해 보는 장사지.
가중치(왼쪽) 한 번 읽기로 하는 연산의 양(오른쪽) 설명용

2.3 용어 풀기 · Forward pass

순전파 = 라인 한 바퀴, 나오는 것은 "잡음 지도"

모델은 층(공정)이 이어진 라인. 층들이 함께 잡음 지도를 예측하고, 덜어내기는 모델 밖에서 설명용

순전파 (forward pass)

입력을 첫 층부터 끝 층까지 한 번 통과시키는 계산. 층 하나가 잡음을 지우는 게 아니라, 층들이 함께 "어디에 잡음이 얼마나"를 계산합니다. 추론은 순전파만 합니다.

분류 모델인가? 아니요

분류는 답 하나를 고름. 디노이저는 밑그림과 같은 크기의 숫자판(잡음 지도)을 칸마다 맞힘. 학습 손실도 −log가 아니라 차이의 제곱 평균

그러면 50단계는?

빼기는 모델 밖(샘플러)의 간단한 계산. 무거운 건 순전파입니다. 50단계면 50바퀴…가 아니라 실제로는 100바퀴. 왜? → 다음 장

2.3.1 Image Generation Model Architecture · 용어 풀기

그림을 타일로 잘라 단어처럼 줄 세운다

SDXL이란

Stable Diffusion XL. Stability AI가 2023년 공개한 이미지 생성 모델로, 누구나 내려받아 쓸 수 있습니다. 1024×1024 그림이 기본이고 디노이저가 두 대(다음 장)인 것이 특징입니다.

확산 트랜스포머란

글 공장의 기계(트랜스포머)를 그림에 쓴 것. 글은 토큰을, 그림은 밑그림을 2×2·4×4칸씩 자른 조각(패치)을 단어처럼 줄 세워 처리합니다 책. 다 다듬으면 VAE가 다시 큰 그림으로 펼칩니다.

SDXL의 디노이저는 U-Net 안에 트랜스포머 블록을 넣은 구조, Qwen Image 같은 최신 모델은 통째로 확산 트랜스포머

한도선은 모델이 VRAM에 다 들어갈 때의 이야기

넘치면 남는 가중치를 순전파마다 PCIe로 실어 와야 합니다. PCIe는 VRAM 통로보다 수십 배 좁아서, 용량 부족이 곧 메모리 병목이 됩니다.

2.4.2 LLM Inference Bottlenecks

프리필은 질문 한꺼번에(계산), 디코드는 답 하나씩(메모리)

프리필 (Prefill) = 질문 읽기

질문 전체를 한꺼번에 읽고 작업 일지(KV 캐시)를 만듦. 설계도 한 번에 큰 계산 → 계산 병목. 사용자에겐 첫 글자까지 대기(TTFT)

디코드 (Decode) = 답 쓰기

답을 한 토큰씩. 토큰마다 설계도 전체를 들여오는데 계산은 조금 → 메모리 병목. 사용자에겐 글자가 흘러나오는 속도(TPS)

공통

두 단계 모두 가장 비싼 연산은 어텐션 책. 다음 장에서 어텐션이 무엇인지 보고, 직접 계산합니다(d = 128, N = 4096)

그림 2.14

2.5 Optimizing Attention

가장 비싸고 예민한 공정, 어텐션

왜 비싸고 예민한가 책

  • 입력 길이의 제곱으로 늘어남
  • 디코드에서는 KV 캐시 덕분에 선형(길이에 비례)이지만, 그것조차 길면 매우 비쌈

2.5 구현 개선 ① FlashAttention

중간 재고를 창고에 넣지 않는다

  • 가장 유명한 어텐션 구현 계열 책
  • 기본 알고리즘은 몇 줄, FlashAttention은 수만 줄의 손으로 합친(fused) 커널
  • GPU마다 다른 코드: H100용 ≠ B200용 책
  • N×N 점수표(S·P)를 창고에 넣었다 빼지 않고, 작업대에서 조각(블록)씩 이어 처리 → 프리필·영상 생성에 특히 유용
GPU마다 코드가 다르다면… 2018년 우리 Quadro용 최신 커널은 누가 만들어 주지?
N=4096·d=128 어텐션. 토글 = S·P 왕복을 뺀 단순화(실제 커널은 블록마다 K·V를 다시 읽음) 설명용
2.5 구현 개선 ② PagedAttention

창고 빈칸 아무 데나, 위치는 조회표에

  • KV 캐시는 금방 커져 GPU 메모리를 채우고, 읽는 데도 시간이 듦 책
  • KV 캐시를 블록(페이지)으로 나누고 조회표로 찾음
  • 하나의 연속된 큰 메모리 대신 조각난 메모리에도 저장 책

칸 = 메모리 블록, 색 = 요청. 연속 할당은 요청마다 최대 16칸을 미리 잡음(빨강 = 예약했지만 빈 칸) 설명용
같은 창고에 손님을 더 받으니, GPU 한 장당 매출이 늘죠.
